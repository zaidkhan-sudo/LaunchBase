1 High-Level System Architecture

The backend operates as two isolated processes: the API Server and the Build Worker. They communicate asynchronously via Redis (Pub/Sub for logs, Queue for jobs) and MongoDB (persistent state).

3 Real-Time Log Streaming Pipeline

The Build Worker and API Server are separate OS processes. Socket.IO connections live on the API server, but logs are generated by the Worker. Redis Pub/Sub bridges this gap while MongoDB provides durability.

4 Project Lifecycle State Machine

Projects and their Deployments transition through these distinct states. Stuck builds are automatically killed by a 15-minute Watchdog cron job.

stateDiagram-v2 [*] --> IDLE: Default Schema State IDLE --> QUEUED: POST /api/project or Git Push QUEUED --> BUILDING: Worker picks up job (Cloning/Building) BUILDING --> DEPLOYING: Image Pushed, provisioning AWS DEPLOYING --> READY: ALB Health Checks Passed BUILDING --> FAILED: Build Error / 15m Watchdog Timeout DEPLOYING --> FAILED: Container Crash / Health Check Timeout FAILED --> QUEUED: Manual Redeploy / Git Push READY --> QUEUED: New GitHub Webhook Push

5 Infrastructure Teardown Flow

AWS requires strict reverse-order deletion. You cannot delete a Target Group if an ECS Service or ALB Listener Rule still references it. The API Server coordinates this dance synchronously.

graph LR Start["DELETE /api/project/:id"] --> ECSSvc["1. deleteECSService"] ECSSvc --> Drain["2. Wait 8s Drain"] Drain --> Rule["3. deleteListenerRule"] Rule --> Target["4. deleteTargetGroup"] Target --> Mongo["5. Delete from DB"] Mongo --> End["Project completely erased"]

6 Key Files in Your Backend

  • src/app.js: Express setup, routes, CORS, and raw webhook parsing via express.json hooks.
  • src/workers/buildWorker.js: The entire asynchronous CI/CD orchestrator. Clones, builds, pushes to ECR, provisions ALB rules, and spins up ECS services.
  • src/services/log.service.js: Strips ANSI escape codes, immediately publishes logs to Redis, and batches database writes.
  • src/services/alb.service.js: Handles AWS Target Groups and Listener Rules with robust naming and free-priority-slot detection.
  • src/services/ecs.service.js: Handles Fargate tasks, zero-downtime CreateService deployments, and AWS rollout circuit-breakers.
  • src/services/webhook.service.js: Verifies cryptographic HMAC signatures of incoming GitHub push events.
  • src/sockets/index.js: Subscribes to Redis, authenticates WebSocket connections, and funnels events into user-specific project rooms.
