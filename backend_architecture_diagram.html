2 Step-by-Step Sequence: What Happens After Project Creation?

Here is the exact timeline of events when a user submits a new project:

3 Project Lifecycle State Transitions

Every project in MongoDB moves through these states during its build and deployment cycle:

stateDiagram-v2 [*] --> IDLE: Default Schema State IDLE --> QUEUED: POST /api/project or Git Webhook Push QUEUED --> BUILDING: Build Worker dequeues job from Redis BUILDING --> READY: Docker Image built and tagged successfully BUILDING --> FAILED: Git clone error / Docker build error / 15m Timeout FAILED --> QUEUED: Next Git Push / Manual Re-queue READY --> QUEUED: Next Git Push (Webhook CI/CD Trigger)

4 Key Files in Your Backend

  • server.js & src/app.js: Express API server entry point and CORS/logging middleware configuration.
  • src/controllers/project.controller.js: Handles handleCreateProject, creates MongoDB record, and pushes job to Redis.
  • src/services/queue.service.js: Wraps ioredis with pushToBuildQueue (LPUSH) and popFromBuildQueue (BRPOP).
  • src/workers/buildWorker.js: Standalone background worker process that pulls jobs from Redis, clones git repos, and builds Docker images.
  • src/services/docker.service.js: Automatically generates Dockerfiles for Node.js, Python, and Go projects, and executes docker build.
  • src/services/webhook.service.js: Verifies GitHub HMAC SHA-256 webhook signatures and re-queues builds on push events.
